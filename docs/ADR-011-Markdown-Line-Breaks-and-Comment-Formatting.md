# ADR-011: Markdown Line Breaks and Comment Formatting

**Status:** Accepted  
**Date:** 2026-08-11

## Context

Task descriptions already use server-side Markdown rendering with CommonMark and
Symfony HtmlSanitizer. Two UI gaps remained:

- A line entered in the description textarea was rendered as part of the same
  visual line after saving.
- Comments were plain text and did not offer the Markdown toolbar available for
  descriptions.

## Decision

Keep one Markdown pipeline for descriptions and comments. Configure CommonMark's
soft-break renderer to emit `<br>` so normal textarea line breaks are preserved.
Comment content is converted to sanitized HTML in `GetTaskHandler`, then rendered
in the task view. Raw Markdown remains the stored value.

The comment composer and admin comment editor now provide the same lightweight
toolbar as the description editor:

- bold
- italic
- inline code
- unordered list
- link
- quote
- fenced code block

Toolbar actions only insert Markdown into the textarea. They do not introduce a
client-side Markdown dependency.

## Files Changed

- `app/src/Core/UI/Twig/MarkdownConverter.php` — preserve soft line breaks.
- `app/src/TaskManagement/Application/Query/GetTaskHandler.php` — add sanitized
  `contentHtml` for comments.
- `app/templates/task/show.html.twig` — Markdown toolbar for new and edited
  comments; render formatted comment content; explicit spacing for rendered
  paragraphs and line breaks.

## Security

Comment HTML is generated by the existing CommonMark converter and passed through
the existing HtmlSanitizer allowlist. User-provided HTML is never rendered
directly.

## Verification

`git diff --check` passes. Symfony lint and PHPUnit require the project's PHP or
Docker runtime; neither executable is available in the current shell.
